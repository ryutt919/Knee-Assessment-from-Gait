# Project Update Report - v1.0

## 📌 Version Summary

MVNX 원본 읽기 병목(6시간 소요) 완벽 제거 및 그룹(4종)별 초고속 시계열 Parquet 테이블 변환 파이프라인 전면 구축 성공.

## 💬 User Requirements

- [X] 시계열 원본 자체를 단순 통계량으로 뭉개지 않고 프레임 단위로 완벽하게 보존
- [X] `pd.read_excel`로 인한 기형적인 로딩 속도를 완벽하게 제거 
- [X] 거대한 XML 원본 데이터를 파싱하여 완벽한 2차원(Row-Col) 형태의 시계열 구조로 평탄화(Flattening)
- [X] 뿔뿔이 흩어진 데이터를 4개의 그룹(`ACLD`, `ACLR`, `Healthy adolescents`, `Healthy adults`)별 1개의 산출물(Parquet)로 병합 출력
- [X] 그룹/SubjectID/가속도(Pace/Speed) 메타데이터 속성을 컬럼으로 데이터에 밀어넣을 것

## 🛠 Key Changes

### 1. 코드 수정 (Logic)
- `utils/mvnx_parser.py`: Python 기본 내장 `xml.etree`의 `iterparse` 메모리 반환 방식을 도입. 1프레임 안의 방대한 정보들을 컬럼(`orientation_0` ~ `jointAngleErgoXZY_17` 등) 600여 개로 분해(Flattening)하는 XML 전용 파서 모듈 개발.
- `scripts/preprocess_all.py`: `concurrent.futures`를 적용해 1,090개의 방대한 MVNX 파일을 CPU 다중 코어로 동시 파싱. 파싱된 데이터들을 메모리 위에서 `pd.concat`하여 거대한 4개의 Parquet 포맷 파일(예: `ACLD.parquet`)로 압축 저장.

### 2. 설정 변경 (Config)
- **Metadata Injection:** 폴더 경로(`group/subject/gait/speed/file`) 구조를 역산하여 내부 데이터에 고정 컬럼(`group`, `subject_id`, `speed`, `file_name`)으로 강제 주입하는 경로 파싱 시스템 적용.

## ✅ Verification Results

- **Test Case 1 (XML 파싱 컬럼 테스트):** `Healthy adults.parquet` 로드 시 332,902개의 시간 프레임(Row), 693개의 시계열 숫자 데이터(Column)의 완벽한 2차원 표(Tabular) 구조 이식 확인 (성공).
- **Test Case 2 (벤치마킹 체감 속도):** 수십 개로 쪼개진 원본 파일 대비, 약 2MB 수준으로 극도로 압축된 `.parquet` 로드 시간이 약 **8.3초** 이내로 동작함을 `check_columns.py` 스크립트를 통해 체감 검증 (이제 딥러닝에서 `pd.read_parquet(경로)` 1줄로 즉시 데이터 튜닝 가능).

## 📝 Issues & Resolutions

- **이슈:** 파서의 초기 버전(`iterparse` end 이벤트 방식) 기동 시, `<frame>` 태그 내부의 자식 정보(예: `<position>`)가 부모 태그를 인식하기 전 메모리에서 조기 반환되어 소실되는 버그 발생 (메타데이터를 제외한 숫자 데이터 전체 증발).
- **해결 방안:** events에 `"start"`와 `"end"`를 결합 추적하는 `in_target_frame` 불리언(Boolean) 상태 스위치 구문을 추가하여 완벽한 문자열 추출 보장 및 메모리 누수 방지로 688개 시계열 값 복구 성공.
